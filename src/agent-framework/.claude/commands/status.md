# /status コマンド

REQの進捗状況を確認・表示します。

## 使用方法

```
/status [REQ-YYYY-NNN]
```

## 引数

- `REQ-YYYY-NNN`: 依頼番号（任意）
  - 指定あり: 指定REQの詳細状態を表示
  - 指定なし: 全REQの一覧を表示

---

## 実行内容

### REQ番号指定なしの場合

`documents/` 配下の全REQフォルダを走査し、一覧表示:

```markdown
## REQ進捗一覧

| REQ番号 | 現在Phase | ステータス | 開始日 |
|---------|-----------|-----------|--------|
| REQ-2026-001 | Phase 5 | 🔄 実装中 | 2026-01-15 |
| REQ-2026-002 | Phase 2 | ⏳ レビュー待ち | 2026-01-20 |

### サマリー
- 進行中: 2件
- 完了: 0件
```

### REQ番号指定ありの場合

`documents/REQ-YYYY-NNN/00_進捗管理.md` を読み込み、詳細表示:

```markdown
## REQ-2026-001 詳細状態

### 基本情報
| 項目 | 内容 |
|------|------|
| REQ番号 | REQ-2026-001 |
| 開始日 | 2026-01-15 |
| 現在Phase | Phase 5（実装） |

### Phase進捗

| Phase | 成果物 | 状態 | 承認日 |
|-------|--------|------|--------|
| 0 | 依頼受領 | ✅ | 2026-01-15 |
| 1 | ヒアリング | ✅ | 2026-01-16 |
| 2 | 要求定義書 | ✅ | 2026-01-18 |
| 3 | 設計書 | ✅ | 2026-01-20 |
| 4 | WBS | ✅ | 2026-01-22 |
| 5 | 成果物 | 🔄 | - |
| 6 | 完了報告 | ⏳ | - |
| 7 | Issue管理 | ⏳ | - |

### 次のアクション
Phase 5（実装）を完了後、`/next-phase REQ-2026-001` を実行してください。
```

---

## エラー処理

### REQが見つからない場合

```
⚠️ REQ-YYYY-NNN が見つかりません。

確認してください:
- documents/REQ-YYYY-NNN/ フォルダが存在するか
- REQ番号の形式が正しいか（REQ-YYYY-NNN）
```
